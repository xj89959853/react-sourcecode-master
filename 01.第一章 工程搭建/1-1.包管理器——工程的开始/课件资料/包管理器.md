# 包管理器的选择和使用

### 思考部分：

1、怎么创建项目？随着前端发展，现在创建一个前端项目可不仅仅是新建一个目录，项目的创建其实是进行工程环境搭建，根据要解决的问题将对应的工程化工具配置到项目中。

2、在只有一个空目录的情况下，应该用什么工程化工具来解决呢？一个能管理其他工具的工具。

`书包的示例`

在工作开发中，所有不是本项目或者js自带的功能以及工具，都被叫依赖，而管理依赖的工具，就是包管理器。

3、明确了要配置包管理器，前端常见的包管理器有npm、yarn和pnpm，怎么选择呢？我们来简单看一下pnpm的优势

- 占用空间小，pnpm将相同依赖的包存储在全局位置，避免每个项目重复存储相同依赖的包

- 大型和复杂依赖时，安装速度更快。因为yarn和npm是将依赖复制过来，而pnpm是创建链接。

- 解决幽灵依赖

4、确定选择了pnpm后，我们就该进行项目初始化了。就是通过`init`命令创建一个package.json文件，初始化之后要做什么呢？我们先看一下官方文档，在开发react项目时，最基础的要安装react和react-dom，这是两个依赖。在react源代码中，这两个依赖都在packages目录下，我们把这种多个独立的项目集成在一个目录下的仓库结构叫monorepo。

5、monorepo结构有什么优点和缺点呢？

- 优点：
  
  - 统一管理，都在一个仓库中，控制和协作更集中
  
  - 模块共享，公共方法可以共用

- 缺点：
  
  - 权限不好控制，不存在只能访问一部分
  
  - 不适合单体业务量庞大的，或相对独立的业务

6、react的源码为什么适合monorepo？

- 不同包之间存在相互依赖的情况

- 单个包业务聚焦

- 单个包体积不大

7、所以那我们下面的问题就是，如何在pnpm中构建monorepo仓库？主要是以下两种方式可以实现

- pnpm-worspace.yaml（官方推荐）

- package.json（个人推荐，兼容性好）

### 实操部分：

1、 安装pnpm

```bash
#安装pnpm
npm install -g pnpm

#检查pnpm是否安装成功
pnpm -v
```

2、初始化项目

```bash
#进入到工程根目录
cd my_react

#初始化项目
pnpm init
```

3、检查并修改package.json文件

```json
{
  "name": "my_react",
  "private": true,  // 防止当前项目意外发布
  "workspaces": [   // monorepo 工作区配置
    "packages/*"
  ],
  "engines": {      // 指定 Node.js 版本要求
    "node": ">=16.0.0"
  }
}
```

**注意**：private属性，只会影响当前package.json所在的目录，而不会影响子包，子包是相对独立，子包是否能发布取决于子包的package.json中是否配置了这个属性。

4、要安装依赖到根目录中，需要加`-w`参数

```bash
pnpm i -w <package_name>
```
