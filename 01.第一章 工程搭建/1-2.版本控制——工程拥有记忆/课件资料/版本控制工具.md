# 版本控制工具

### 思考部分：

1、配置了包管理之后，我们的项目现在还有个比较大的问题，是什么呢？就是项目本身没有“记忆”。

2、什么叫项目没有“记忆”呢？就是我们当前的项目每次修改之后，只能获取到当前的文件内容，而无法知道之前的某一次修改后的文件状态。就好像`书包只能知道当前装了什么东西，不知道昨天装了什么东西一样`。

3、那没有“记忆”又会有什么影响呢？要知道，我们在做的是一个工程，工程就不是一个人一下子做完的，而是分阶段，多人协作。

4、这里就会出现几个问题。

- 分阶段，每一个需要记录的节点能保存当时的状态。

- 可共享，便于多人获取。

- 可对比差异，因为大家操作的是同一个文件内容，所以在修改之后需要能清楚的知道改的哪些文件，改了什么内容。这样最终才能获取文件修改后的最终状态。

5、那怎么解决上面的问题呢？其实就是需要版本管理工具。就是将每一次需要记录的文件内容形成一个版本，记录下来，然后对版本进行对比，导出等操作。

6、常见的版本控制工具有哪些？主要是两类，集中式版本控制（CVCS），代表是svn。分布式版本控制（DVCS），代表是git。在实际工作中我们基本遇到的最多的就是git。

7、为什么基本上遇到的项目都是用git而不是svn呢？这就要说说他俩的区别了。

- svn的实现特点：
  
  - 集中式：所有操作，提交，合并，对比，以及历史版本查看全部都需要依赖svn服务器，无法在本地操作
  
  - 记录主要是文件的变化，虽然也会定期生成基线版本（base version），但基本上想要获取某一个版本的内容都需要之前的一些版本加上差异变化，计算出目标版本的内容

- git的实现特点：
  
  - 分布式：本地的仓库就是一个完整的仓库，所有操作，提交，合并，对比都可以在本地进行，更加方便和灵活
  
  - 记录的是文件的快照，快照其实就包含了当前文件版本的内容，上一个提交的指针，以及一些版本信息。所以想要获取某一个版本的内容，只需要将一个指针指向目标版本既可。

8、那么接下来，该怎么用git初始化一个项目呢？

- init初始化项目：就是声明当前项目是个仓库

- 配置.gitignore文件：仓库就是管理文件，但是有些文件我们不希望被管理，也就是不希望被共享的文件，比如node_modules，.DS_store，dist，而且还有就是本机开发环境下的一些不需要被共享的配置文件。

### 实操部分：

1、git项目初始化

```bash
git init
```

2、添加.gitignore文件

```gitignore
node_modules/
.DS_Store
```

3、查看git是否配置正常

```bash
git status
```
