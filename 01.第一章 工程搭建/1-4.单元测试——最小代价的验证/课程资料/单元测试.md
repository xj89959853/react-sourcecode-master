# 单元测试

### 思考部分：

1、我们已经配置完写代码时需要的工程化工具，接下来要配置什么呢？单元测试

2、大家应该都听过单元测试，但实际开发中，真正经常用单元测试的情况比较少，一般业务开发我们将项目跑起来，然后用mock，console和debug来进行调试。但是一般在开源框架中，基本上都能见到带有`test`字段的文件。

3、那为什么开源库需要单元测试，而在业务开发的时候经常用不到呢？主要是以下几点。

- 可运行性不同。一般的业务项目都是可运行的，而框架一般是导出方法，本身是运行不了的。

- 关注点不同。架构关注的是程序跑起来的稳定，而一般页面开发关注在页面实现上，页面实现只是整体项目的一小部分。

- 代码复杂度和调用链不同。一般的业务开发，公用方法放到share，公用UI抽出个组件，然后就在页面中直接调用，一般层级比较浅。但框架的调用层级往往都很长，这样就涉及如果完整测试，调试过程中，出错时，排查代码就会比较难。

4、而单元测试就可以解决上面的问题，单元就是不可分割，讲逻辑切割成最小内容，然后不用运行项目，就可以看到每个功能运行后的结果。总结来说就是一句古话：不积跬步无以至千里。每一个最小单元都通过了测试，那后面整体测试时通过率会大幅提高。

5、因为我们这个是前端项目，所以选择的是开箱即用，容易上手，而且功能比较全面的jest。那怎么配置为项目配置jest呢？主要是四步

- 安装jest依赖

- 创建配置文件

- 增加test命令

- 测试

### 实操部分：

1、安装jest依赖：

```bash
# 安装 Jest 及相关依赖
pnpm add jest @types/jest @testing-library/jest-dom ts-jest jest-environment-jsdom
```

> 说明：

- **jest：** 核心，JavaScript/TypeScript 测试框架，提供测试运行、断言、Mock 等功能。

- **ts-jest：** Jest 的 TypeScript 预处理器，允许直接测试 `.ts` 文件（无需手动编译）。

- **@types/jest：** 提供 Jest API 的类型定义（如 `describe`, `it`, `expect` 的类型提示）。

- **@testing-library/jest-dom：** 扩展 Jest 的 DOM 断言（如 `.toBeInTheDocument()`）。

- **jest-environment-jsdom：** 模拟浏览器环境（Jest 默认是 Node.js 环境，需此包支持 DOM API）。

2、创建jest.config.js

```javascript
module.exports = {
  // 基础配置
  preset: 'ts-jest',                // 使用 ts-jest 处理 TypeScript
  testEnvironment: 'jsdom',         // 指定测试运行时的环境类型。决定了测试运行时的全局变量和API，例如在浏览器环境中，window和document等全局变量是可用的，而在Node.js环境中则不可用。在测试执行之前，用于初始化测试环境。决定了测试运行的环境类型

  // 路径配置
  roots: ['<rootDir>'],    // 测试文件根目录
  testMatch: [                      // 测试文件匹配模式
    '**/__tests__/**/*.+(ts|tsx|js)',
    '**/?(*.)+(spec|test).+(ts|tsx|js)'
  ],

  // 模块解析配置
  moduleNameMapper: {
    // 路径别名
    '^@mini_react/(.*)$': '<rootDir>/packages/$1/src',
  },

  // 转换配置
  transform: {
    '^.+\\.(ts|tsx)$': 'ts-jest'   // TypeScript 文件转换
  },

  // 测试环境设置，指定一组文件路径，这些文件将在测试环境初始化后执行。允许在测试执行之前配置测试框架或执行一些初始化代码，例如设置全局变量、添加自定义匹配器等。在测试环境初始化之后，但在测试代码执行之前。用于在测试执行前进行额外的配置和初始化
  setupFilesAfterEnv: [
    '@testing-library/jest-dom'  // DOM 匹配器
  ],

  collectCoverage: true,            // 收集覆盖率
  coverageDirectory: 'coverage',    // 覆盖率报告输出目录
};
```

3、添加test命令

```json
{
    "scripts"：{
        "test": "jest"// 测试相关
    }
}
```

4、测试

```javascript
//index.ts
function sum(a:number,b:number){
    return a+b;
}
export default sum;

//index.test.ts
import sum from './index';

describe('sum',()=>{
    it('should return 3',()=>{
        expect(sum(1,2)).toBe(3);
    });
});
```

覆盖率说明：

- **Statements 覆盖率**：表示代码中每个语句的执行情况。

- **Branches 覆盖率**：表示条件语句（如 `if/else`）的执行情况。

- **Functions 覆盖率**：表示每个函数的执行情况。

- **Lines 覆盖率**：表示代码中每行的执行情况。

5、其实最后还有额外的一步，就是因为每次测试完之后会生成coverage目录存储单元测试覆盖率，所以我们需要再`.gitignore`文件中忽略这个目录

```gitignore
coverage/
```
