# 打包

### 思考部分：

1、我们已经完成了文件管理类的，书写代码时的，写完代码的测试，那接下来该配置什么呢？就是打包。

2、打包工具基本上目前每个项目都会有，这里就不过多介绍打包的意义，咱们重点来讲一下打包工具的选择。当前前端主流的打包工具相信大家都听过，主要是webpack，vite，rollup，那这三个工具该怎么选呢？我们来一起简单对比一下这三个工具。

3、对比工具一般首先要明确我们当前需要解决的问题，并且这个问题里哪些内容是最重要的？就是打包后体积。因为我们打包后的产物是要给别人引入，所以大小就很重要。

4、带着这个指标我们再来对比一下三个工具的特点

- rollup：打包产物体积最小（无运行时模块），专注js文件处理，无热更新

- webpack：功能全面，生态完整，能处理各种资源，有热更新，打包内容较大（有运行时模块）

- vite：开发环境时启动快，有热更新，生产打包时依赖rollup

一般开源库的开发用rollup，大型企业级应用可以在webpack和vit中选择

### 实操部分：

1、安装rollup依赖

```bash
#核心依赖
pnpm add -D rollup @rollup/plugin-babel @babel/core @babel/preset-env @rollup/plugin-typescript
```

> 说明：

- **rollup：** 核心功能。专注于将 JavaScript 模块打包成适合浏览器或 Node.js 的代码。

- **@rollup/plugin-babel：** 将 Babel 集成到 Rollup 中。

- **@babel/core：** 任何 Babel 转换都依赖它（解析代码、生成 AST、转换代码）。

- **@babel/preset-env：** 需要考虑浏览器兼容性，需要es语法降级，需要用这个

- **@rollup/plugin-typescript：** 将 TypeScript 集成到 Rollup 中。

2、书写脚本

```javascript
// scripts/rollup/build.js
const path = require('path');
const rollup = require('rollup');
const { babel } = require('@rollup/plugin-babel');
const typescript = require('@rollup/plugin-typescript');

// 定义包配置
const packages = [
  {
    name: 'test',
    input: 'packages/test/index.ts',
    outputs: [
      {
        file: 'packages/test/dist/index.js',
        format: 'umd', 
        name: 'Test'
      }
    ]
  },
  // 其他包配置...
];

async function build() {
  // 遍历每个包
  for (const pkg of packages) {
    const config = {
      input: pkg.input, // 入口文件（必须是 TypeScript 文件）
      plugins: [
        babel({
            presets: ['@babel/preset-env'], // 预设，根据你的目标环境自动确定需要转换哪些 JavaScript 特性，默认会转换为es5
          }),
        typescript({
          tsconfig: './tsconfig.json',// 指定 TypeScript 配置文件
          exclude: ['**/*.test.ts'],    // 排除测试文件
          declaration: true,      // 生成类型声明
          declarationDir: path.dirname(pkg.outputs[0].file) // 类型声明输出目录, TypeScript 的声明文件输出目录 (declarationDir) 必须位于 Rollup 输出文件目录内。
        }),
      ]
    };

    // 创建 bundle
    const bundle = await rollup.rollup(config);

    // 生成输出
    for (const output of pkg.outputs) {
      await bundle.write(output);
    }
  }
}

build().catch(console.error);
```
