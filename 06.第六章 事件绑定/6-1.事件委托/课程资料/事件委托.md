# 监听root

### 思考部分：

1、事件常用的写法有哪些？

- dom属性方式：`<button onclick=""/>`

- 事件监听器：addEventListener()

2、使用dom方式有什么问题？因为作用于问题，需要每次将要绑定的方法挂在到全局上`window.handleClick`

3、使用事件监听器核心需要什么？dom元素，绑定方法

4、绑定到哪儿？

- 目标元素上：在completeWork阶段可以拿到元素和方法，可以在这个阶段上实现。好处是简单，元素和方法都是现成的。坏处是，对于要绑定的元素数量未知，可能会占用很大内存用来存储事件监听器

- 根元素上：在createContainer的时候可以拿到元素对象，但是没有具体的方法。好处是节省内存，只需要对一个元素进行事件监听，监听器数量可限制。坏处是绑定方法不能用现成的，需要手动实现一个

5、为什么绑定到根元素可以实现所有元素的监听？浏览器事件传播机制。

window->document->...->target->...->document->window

- 捕获阶段：从外向内的过程，从window到target元素的过程

- 目标阶段：对于target绑定的事件以及方法的触发处理

- 冒泡阶段：从内向外的过程，从target回到window的过程

而react有一个根元素，所有子元素都在这根元素之下，所以理论上可以通过监听root实现对所有子元素的事件监听。

### 实操部分：

1、修改FiberReconciler.ts

```typescript
/**
 * 创建FiberRoot,HostRootFiber,并建立关联
 * @param containerInfo 
 */
export function createContainer(containerInfo:HTMLElement){
    const root = createFiberRoot(containerInfo);
    const hostRootFiber = createHostRootFiber();
    hostRootFiber.stateNode = root;
    // 根元素添加事件监听
    root.containerInfo.addEventListener('click',()=>{
        console.log('root click')
    })
    return hostRootFiber;
}
```
